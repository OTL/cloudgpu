# 課金を抑えるための運用ルール

## 大原則

RunPod の課金は **秒単位**。つまり「立ち上げっぱなしにしない」ことが 9 割を占める。
残りの 1 割はストレージの置き場所の話。

## 1. Stop ではなく Terminate

| 状態 | GPU 課金 | ディスク課金 |
| --- | --- | --- |
| Running | あり | あり |
| Stopped | なし | **あり**（Pod ボリューム分、$0.2/GB/月 前後） |
| Terminated | なし | なし（Network Volume 分だけ残る） |

Stop は「GPU を離すが、その Pod のディスクは押さえておく」状態。100GB の Pod を
stop で放置すると月 $20 が黙って溶ける。しかも stop 中でも GPU が他人に取られて
再開できないことがあるので、確保の意味も薄い。

**永続させたいものを全部 `/workspace` に置いておけば、terminate が怖くなくなる。**
このリポジトリの provision.sh はそのためにある。

## 2. GPU の選び方

生成 1 枚あたりのコストは `時間単価 ÷ スループット` なので、単価が安いだけの
GPU が得とは限らない。

| GPU | VRAM | 目安単価 | 向き |
| --- | --- | --- | --- |
| RTX 4090 | 24GB | $0.3–0.5/h | 標準。FLUX dev も余裕 |
| RTX A5000 | 24GB | $0.2–0.3/h | 4090 の 6〜7 割の速度。時間あたりでは得なことも |
| RTX A4000 | 16GB | $0.17–0.25/h | fp8 モデルなら動く。SDXL 中心なら十分 |
| A100 / H100 | 40–80GB | $1.5+/h | 画像生成には過剰。LLM を載せる段になってから |

迷ったら 4090。VRAM 24GB あると「モデルが載らない」で悩む時間（＝課金時間）が消える。

## 3. Spot（Interruptible）

単価は 5〜7 割。より高い入札があると予告なしに落とされる。

- 落とされて困らない使い方（試行錯誤、バッチ生成）なら常用してよい
- Network Volume 上のデータは落とされても残る
- 生成中のジョブは消えるので、大量生成は小分けにキューする

## 4. Serverless に移すタイミング

「毎日ちょっとだけ叩く」「アプリから API で呼ぶ」段階になったら Serverless
（scale to zero）のほうが安い。逆に、対話的に試行錯誤する段階では
コールドスタート（モデルのロードに数十秒〜）が挟まる分、実質的に高くつく。

判断の目安: **1 回のセッションが 30 分を超えるなら Pod、数分で終わるなら Serverless。**

## 5. その他

- ダウンロードは GPU 課金中に走る。大きいモデルは一度取れば Volume に残るので、
  初回だけ我慢すればよい。頻繁に Pod を作り直すなら安い GPU を選んで
  プロビジョニングだけ済ませ、terminate してから本番の GPU で作り直す手もある
- Network Volume の容量は増やせるが減らせない。最初から大きく取らない
- 使わなくなったモデルは消す（`du -sh /workspace/ComfyUI/models/*` で確認）
- RunPod が高いと感じたら vast.ai が同等 GPU で 2〜3 割安いことが多い。
  ただし UI とホストの品質はばらつく
